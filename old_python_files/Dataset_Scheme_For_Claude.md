# Dataset Scheme for Claude Distillation (SFT)
**Target Model:** Llama 3.2 3B Instruct (SFT via Unsloth)  
**Task:** Social Reply Generation — 3 suggestions (Natural / Polite / Like You)  
**Distillation Source:** Claude  
**Format:** JSONL — raw data layer + training messages layer

---

## 1. Design Principles

- **SFT = imitation**: The model learns to produce the same output Claude would. No scoring, no consequence evaluation — that belongs to GRPO.
- **Mirror the app exactly**: Schema fields map 1-to-1 to `ConversationInput` in `Models.swift`. No invented fields that the app doesn't use.
- **Two task types only**: `from_scratch` (no draft) and `rewrite` (has draft). Nothing else for v1.
- **Speaker = real user ID**: `"me"`, `"alice"`, `"bob"` etc. — not the string `"other"`. Display names are resolved at prompt-build time via `participants`.
- **Output = 3 suggestions JSON**: Matches `SuggestionOutput` in the app. Fixed labels: `Natural`, `Polite`, `Like You`.
- **conversation_history**: Max **10 turns**, average target **4–6 turns**. Truncate from the front if needed (keep most recent).

---

## 2. Raw JSONL Schema (Data Layer)

This is what you save, label, and clean. Generated by calling Claude with the same prompt the app uses.

```json
{
  "sample_id": "social_000001",
  "task_type": "from_scratch",
  "self_id": "me",
  "participants": [
    {"id": "me",    "name": "Me",    "is_self": true,  "relationship": null},
    {"id": "alice", "name": "Alice", "is_self": false, "relationship": "friend"}
  ],
  "conversation": [
    {"speaker": "alice", "text": "hey are you free this weekend?"},
    {"speaker": "me",    "text": "maybe, things are a little busy rn"},
    {"speaker": "alice", "text": "all good? haven't heard from you in a bit"}
  ],
  "reply_to": "alice",
  "profile": {
    "tone": "casual",
    "length": "short"
  },
  "draft": "",
  "target": {
    "suggestions": [
      {"label": "Natural",  "text": "Hey! I'm good, just been swamped. What were you thinking?"},
      {"label": "Polite",   "text": "Hey! Sorry for being quiet — things got a bit hectic. I'm doing well though! What's the plan?"},
      {"label": "Like You", "text": "Haha yeah been lowkey off the grid. I'm good tho. What are you thinking?"}
    ]
  },
  "metadata": {
    "source": "claude_distilled",
    "split": "train",
    "format_validated": true
  }
}
```

## 3. Field Reference

| Field | Type | Required | Notes |
|---|---|---|---|
| `sample_id` | string | ✅ | Unique ID, e.g. `social_000001` |
| `task_type` | enum | ✅ | `from_scratch` or `rewrite` |
| `self_id` | string | ✅ | Speaker ID for "me", typically `"me"` |
| `participants` | list | ✅ | Each entry: `id`, `name`, `is_self`, `relationship` |
| `participants[].relationship` | string | ⚪ | `friend` / `classmate` / `manager` / `romantic_interest` / `acquaintance` — optional but useful for diversity tracking |
| `conversation` | list | ✅ | Each entry: `speaker` (user ID), `text`. Max **10 turns**, target **4–6** |
| `reply_to` | string | ⚪ | Speaker ID of who we're replying to. Null = reply to last message |
| `profile.tone` | string | ✅ | e.g. `casual`, `warm`, `professional` |
| `profile.length` | string | ✅ | `short` / `medium` / `long` |
| `draft` | string | ✅ | Empty string `""` for `from_scratch`; user's original text for `rewrite` |
| `target.suggestions` | list | ✅ | Exactly 3 items, labels must be `Natural`, `Polite`, `Like You` in that order |
| `metadata.source` | string | ✅ | `claude_distilled` / `human_written` / `claude_distilled_human_filtered` |
| `metadata.split` | enum | ✅ | `train` / `val` / `test` |
| `metadata.format_validated` | bool | ✅ | Must be `true` before adding to training set |

## 4. Training Messages Format (Llama 3.2 / Unsloth)

Converted from raw JSONL using the same logic as `PromptBuilder.swift`. The system prompt and user prompt are built identically to what the app sends.

### 4.1 `from_scratch` example

```json
{
  "messages": [
    {
      "role": "system",
      "content": "Suggest 3 texts Me can send. Answer the OTHER person's last message.\n\n- Style — honor BOTH the user's personal preferences AND this conversation's settings:\n  • Personal (user, app-wide): tone: casual | length: short\n  • This conversation / thread: tone: not set (this chat does not override) | length: not set (this chat does not override)\n  • Use for THIS reply: Tone: casual | Length: short\n\nRules:\n- Address Alice's message directly. If they asked a question, answer it; do not only repeat what they said.\n- Obey the Style rules above. Short, casual, real person texting unless length is long. Avoid unnecessary exclamation marks (!).\n- Natural = normal | Polite = kinder | Like You = casual punchy\n\nOutput format: one JSON object only, no markdown. Key \"suggestions\" = array of exactly 3 objects. Each has \"label\" (Natural | Polite | Like You) and \"text\" (Me's real reply for THIS chat).\n\nDo NOT reuse the same canned line for all three."
    },
    {
      "role": "user",
      "content": "Conversation:\n  Alice: hey are you free this weekend?\n  Me: maybe, things are a little busy rn\n  Alice: all good? haven't heard from you in a bit\n\nReplying to: Alice\n\n(no draft yet)\n\nReply in JSON as instructed (suggestions array with label + text)."
    },
    {
      "role": "assistant",
      "content": "{\"suggestions\": [{\"label\": \"Natural\", \"text\": \"Hey! I'm good, just been swamped. What were you thinking?\"}, {\"label\": \"Polite\", \"text\": \"Hey! Sorry for being quiet — things got a bit hectic. I'm doing well though! What's the plan?\"}, {\"label\": \"Like You\", \"text\": \"Haha yeah been lowkey off the grid. I'm good tho. What are you thinking?\"}]}"
    }
  ]
}
```

### 4.2 `rewrite` example

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You finish the user's draft into a text they can send. You are Me; answer the OTHER person's last message.\n\n- Style — honor BOTH the user's personal preferences AND this conversation's settings:\n  • Personal (user, app-wide): tone: professional | length: short\n  • This conversation / thread: tone: not set (this chat does not override) | length: not set (this chat does not override)\n  • Use for THIS reply: Tone: professional | Length: short\n\nMUST follow:\n1) FACTS: Keep the draft's meaning. Same times, dates, yes/no, promises, reasons.\n2) DRAFT: Start from the draft — complete or lightly polish it into a full sentence or two.\n3) TARGET: Respond to Bob's message. If they asked a question, answer it.\n4) VOICE: Obey the Style rules above. Real texting — short and casual when length is short.\n\nThree options (different wording):\n- Natural = normal\n- Polite = softer/kinder\n- Like You = closest to how the draft sounds\n\nOutput format: one JSON object only, no markdown. Key \"suggestions\" = array of exactly 3 objects. Each object has \"label\" and \"text\".\n\nDo NOT paste generic filler."
    },
    {
      "role": "user",
      "content": "Conversation:\n  Bob: Can you have the report ready by Friday?\n\nReplying to: Bob\n\nMy draft: \"Friday might be tight, can I get until Monday?\"\nKeep the draft's facts. Expand into a reply to Other's last line. Each of the 3 texts must fit THIS draft.\n\nReply in JSON as instructed (suggestions array with label + text)."
    },
    {
      "role": "assistant",
      "content": "{\"suggestions\": [{\"label\": \"Natural\", \"text\": \"Friday's going to be tight — would Monday morning work? I want to make sure it's accurate.\"}, {\"label\": \"Polite\", \"text\": \"I want to make sure the report is thorough rather than rushed. Would it be okay if I sent it Monday morning instead?\"}, {\"label\": \"Like You\", \"text\": \"Friday might be tough tbh, can I get until Monday? Want to make sure it's solid.\"}]}"
    }
  ]
}
```

### 4.3 Assistant Output Format Rule

The `assistant` turn must **always** be a valid JSON string matching this shape:

```json
{"suggestions": [
  {"label": "Natural",  "text": "..."},
  {"label": "Polite",   "text": "..."},
  {"label": "Like You", "text": "..."}
]}
```

Hard-filter rules before adding to training set:

- [ ] Valid JSON (parseable)
- [ ] `suggestions` key exists and is an array of exactly 3 items
- [ ] Labels are exactly `Natural`, `Polite`, `Like You` in that order
- [ ] No markdown fences (` ```json `) wrapping the output
- [ ] No label has empty `text`
- [ ] All 3 texts are distinct (similarity check: reject if any two are >85% similar)

## 5. Claude Distillation Prompt

When calling Claude to generate `target.suggestions`, use the **same system + user prompts** that `PromptBuilder.swift` would produce for the same input. This ensures training distribution matches inference distribution exactly.

Pseudocode for the generation script:

```python
def build_prompts(sample: dict) -> tuple[str, str]:
    """Mirror PromptBuilder.swift logic in Python."""
    has_draft = bool(sample["draft"].strip())
    profile = sample["profile"]
    participants = {p["id"]: p["name"] for p in sample["participants"]}
    self_id = sample["self_id"]

    # Build conversation lines (display names, not IDs)
    conv_lines = []
    for msg in sample["conversation"]:
        name = "Me" if msg["speaker"] == self_id else participants.get(msg["speaker"], msg["speaker"])
        conv_lines.append(f"  {name}: {msg['text']}")

    reply_to_name = participants.get(sample.get("reply_to"), None)

    system_prompt = SYSTEM_TEMPLATE_DRAFT if has_draft else SYSTEM_TEMPLATE_NO_DRAFT
    system_prompt = system_prompt.format(
        tone=profile["tone"],
        length=profile["length"],
        reply_target=f"{reply_to_name}'s message" if reply_to_name else "the last message"
    )

    user_lines = ["Conversation:"] + conv_lines
    if reply_to_name:
        user_lines.append(f"\nReplying to: {reply_to_name}")
    if has_draft:
        user_lines.append(f'\nMy draft: "{sample["draft"]}"')
        user_lines.append("Keep the draft's facts. Expand into a reply to Other's last line.")
    else:
        user_lines.append("\n(no draft yet)")
    user_lines.append("\nReply in JSON as instructed (suggestions array with label + text).")

    return system_prompt, "\n".join(user_lines)
```

## 6. Dataset Diversity Targets

### Relationship coverage (tracked via `participants[].relationship`)

| Relationship | Target % |
|---|---|
| `friend` | 30% |
| `classmate` | 20% |
| `manager` / `colleague` | 20% |
| `romantic_interest` | 15% |
| `acquaintance` | 15% |

### Task type split

| `task_type` | Target % |
|---|---|
| `from_scratch` | 60% |
| `rewrite` | 40% |

### Profile coverage

- `tone`: cover `casual`, `warm`, `professional`, `direct` — avoid >50% in any single tone
- `length`: roughly 50% `short`, 35% `medium`, 15% `long`

---

## 7. Conversation History Guidelines

- **Max turns**: 10 (hard cap)
- **Recommended average**: 4–6 turns
- **Truncation**: If raw history > 10 turns, keep the **most recent 10** (drop from the front)
- **Never pad**: If only 1–2 turns exist, keep them short — do not invent messages
- **Last message** in `conversation` should always be the message being replied to (from the other person)

---

## 8. Minimum Viable Schema (v1 Quickstart)

For the first generation batch, only these fields are strictly required:

```
sample_id
task_type
self_id
participants          (id + name + is_self; relationship optional)
conversation          (≤ 10 turns)
reply_to
profile.tone
profile.length
draft                 (empty string if from_scratch)
target.suggestions    (3 items: Natural, Polite, Like You)
metadata.source
metadata.split
metadata.format_validated
```

## 9. SFT vs GRPO — What Goes Where

| | SFT (this schema) | GRPO (future) |
|---|---|---|
| **Goal** | Imitate Claude's output format and quality | Learn which reply is socially better |
| **Labels needed** | None — just Claude's output | Reward signal: awkwardness, warmth, consequence label |
| **Consequence field** | ❌ Not needed | ✅ Add here |
| **Scoring** | ❌ Not needed | ✅ Pairwise ranking or scalar reward |
| **Schema complexity** | Minimal | Extended from this schema |

Consequence estimation and scoring should be designed as a **separate GRPO dataset schema** built on top of this one when the time comes.
